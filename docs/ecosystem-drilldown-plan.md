# AI 생태계 단계별 탐색 계획

- 작성일: 2026-09-14
- 상태: 1~3단계 MCP·TypeScript SDK 시범 구현·브라우저·시각 검증 완료
- 연결 문서: [전체 PRD](../PRD.md), [현재 구현과 실행 방법](../README.md)
- 이번 변경: 세부 지도 2개와 애니메이션 진입·복귀 구현. 대표 항목 확대·분야 탭은 후속으로 유지한다.

## 1. 만들고 싶은 경험

전체 지도에는 큰 영역과 대표 제품·프로젝트를 보여준다. 관심 있는 항목의 세부 지도로 들어가면 처음 화면에는 없던 중요한 연관 프로젝트, 확장 도구, 구성 기술이 새로 드러난다. 방문자는 큰 구성을 이해한 뒤 필요한 부분만 단계적으로 깊게 탐색한다.

**핵심은 탐색 단계마다 새로운 발견이 있다는 것이다.** 현재 표시된 항목 중 연결된 것만 추리거나 중심 위치만 바꾸는 것으로는 이 요구를 충족하지 못한다. 세부 설명 패널을 길게 만드는 것만으로도 충족하지 못한다.

세부 요소가 작다는 것은 역할이 구체적이거나 상위 항목의 맥락에서 설명하기 좋다는 뜻이다. 시장 규모나 중요도가 낮다는 뜻은 아니다.

## 2. 현재 상태와 목표의 차이

| 구분 | 현재 구현 | 후속 목표 |
|---|---|---|
| 전체 지도 | 생성형 AI·에이전트 중심 12개 영역·52개 항목·79개 관계 | 큰 축을 설명하는 대표 진입 항목을 편집해서 노출 |
| 항목 선택 | 한 번 클릭은 상세·관계 확인, 더블클릭·버튼은 준비된 세부 지도 진입 | 다른 대표 항목에 같은 진입 경험 확대 |
| 세부 탐색 | 전체 → MCP → TypeScript SDK로 새 항목을 공개하는 2단계 진입 | 콘텐츠가 준비된 다른 대표 항목에 확대 |
| 탐색 경로 | 현재 중심 항목·탐색 경로·뒤로가기·전체 복귀와 선택·위치·포커스 복원 검증 완료 | 새 장면에도 같은 복귀 동작 적용 |
| 분야 확장 | 생성형 AI·에이전트 중심 단일 지도 | 콘텐츠가 준비된 분야부터 상위 탭으로 확장 |

현재 전체 지도의 52개 항목·79개 관계는 유지한다. 세부 전용 12개 항목·20개 관계를 추가한 공유 데이터는 총 64개 항목·99개 관계이며, 이 전체를 첫 화면에 노출하지 않는다. 세부 장면은 각각 중앙 포함 10개 항목·14개 관계·4개 역할 그룹으로 구성한다. 같은 프로젝트의 설명과 출처는 여러 지도에서 공유하며, 향후 최상위 노출 목록은 콘텐츠 편집 과정에서 재검토할 수 있다.

## 3. 합의와 구현 범위

| 상태 | 내용 |
|---|---|
| 합의된 핵심 | 큰 영역·대표 항목을 입구로 삼고, 세부 단계에서 새로운 중요한 연관 요소를 발견하게 한다. |
| 유지할 방향 | 현재 지도와 상세 패널의 시각적 구조, 읽기 쉬운 역할 설명, 공식 근거가 있는 관계를 유지한다. |
| 합의·구현 | 한 번 클릭은 상세 설명, 명시적인 `세부지도 보기` 버튼은 세부 지도 진입으로 사용한다. |
| 합의·구현 | 더블클릭은 같은 기능의 보조 실행으로 제공한다. 모바일·키보드 사용자는 버튼으로 같은 화면에 진입한다. |
| 합의·구현 | 같은 지도 공간에서 선택한 항목을 중심으로 연결선과 카드가 펼쳐지며, 뒤로가기로 이전 선택·위치·포커스를 복원한다. 동작 줄이기 설정을 반영한다. |
| 후속 방향 | 상위 분야 탭과 항목별 세부 탐색을 함께 사용한다. 분야 탭은 범위를, 세부 탐색은 깊이를 바꾼다. |
| 시범 확정 | MCP와 그 안의 TypeScript SDK를 중심으로 2개 장면을 제공한다. 각 장면은 중앙 1개와 주변 9개 항목이다. |
| 미정 | 다음 대표 항목, 향후 최상위 노출 조정, 분야 탭 이름·순서. |

첫 시범 항목은 구성 기술과 관련 프로젝트를 설명하기 좋은 MCP로 선정했다. 이 선택은 해당 항목의 시장 순위를 뜻하지 않는다.

## 4. 방문자 흐름

1. 분야의 전체 지도에서 큰 영역과 대표 항목을 본다.
2. 항목을 한 번 선택해 소개와 역할을 읽는다.
3. `세부지도 보기`를 누르거나 준비된 항목을 더블클릭한다.
4. 선택한 항목이 중심에 놓이고, 해당 맥락에서 중요한 새로운 연관 요소가 펼쳐진다.
5. 연관 요소의 설명·관계 근거를 읽거나 준비된 다음 세부 지도로 이동한다.
6. `뒤로가기` 또는 탐색 경로로 돌아가거나 `전체 지도`로 복귀한다.

MCP 세부 지도는 공식 TypeScript·Python SDK, 기존 FastMCP·Playwright MCP, Registry, stdio·Streamable HTTP, Inspector, Authorization을 보여준다. 그 안의 TypeScript SDK로 진입하면 Zod·Express·Tools·Resources·Prompts가 새로 나타난다. 전송 방식·Inspector·MCP는 동일 항목을 재사용한다. 공식 자료에서 확인한 실제 구현·선택적 연동·규약 관계를 각각 설명한다.

모든 항목에 무한한 다음 단계가 있는 것처럼 보이지 않게 한다. 편집된 세부 지도가 있는 항목에만 진입 동작을 제공하고, 아직 없는 항목은 상세와 공식 자료 탐색으로 마무리한다.

## 5. 화면과 관계 표현

- 전체 지도: 역할 영역과 대표 항목을 먼저 보여주고 초기 연결선은 제한한다.
- 세부 지도: 중심 항목과 역할별 연관 요소를 배치한다. 필요한 연결을 우선 표시하고 더 깊은 항목은 다음 단계에서 공개한다.
- 신규 요소: 이전 단계에서 보이지 않았던 항목을 발견하기 쉽게 표시한다. 이 표시는 최근 출시나 인기 상승을 뜻하지 않는다.
- 관계: `구성 요소`, `확장 도구`, `연동 프로젝트`, `구현 라이브러리`, `기반 기술` 등의 실제 의미와 방향을 설명한다.
- 시각적 위계: 마인드맵처럼 중심에서 펼치되 모든 연결을 부모·자식이나 소유 관계로 취급하지 않는다. 분류·화면 소속과 기술 연결을 분리한다.
- 경로: 현재 중심 항목과 방문 순서를 표시한다. 경로는 실제 의존성 계보가 아니라 사용자의 탐색 기록이다.
- 복귀: 이전 단계로 돌아갈 때 이전 선택과 지도 위치를 복원한다. 반복 방문으로 무한히 중첩되는 상태를 만들지 않는다.
- 상호작용: 연결선·화살표·설명은 카드 위에 표시하되 카드 클릭을 가로막지 않는다. 이동 후 상세 내용과 포커스를 일관되게 갱신한다.
- 모바일: 세부 지도 진입 후 상세 시트가 새 지도를 계속 덮지 않도록 한다. 지도와 충분히 읽을 수 있는 상세 화면을 오갈 수 있게 한다.

## 6. 콘텐츠와 데이터 구성

기존 TypeScript 편집 데이터와 Next.js/React 구조를 활용했다. 세부 콘텐츠는 [data/ecosystem-drilldown.ts](../data/ecosystem-drilldown.ts), 공유 데이터와 장면 정의는 [lib/ecosystem-scenes.ts](../lib/ecosystem-scenes.ts), 탐색 상태는 [lib/ecosystem-navigation.ts](../lib/ecosystem-navigation.ts)에서 관리한다. 이 기능을 위해 DB·관리자 화면·자동 수집을 추가하지 않았다.

| 데이터 | 책임 |
|---|---|
| 항목 | 고유 ID, 이름, 종류, 역할, 상세 설명, 공식 링크, 공개 범위·라이선스, 출처·확인일 |
| 관계 | 실제 양 끝 항목 ID, 의미·방향, 관계 설명, 공식 근거·확인일 |
| 지도 장면 | 고유 ID, 제목, 중심 항목, 보여줄 항목·관계 ID, 역할별 배치 그룹 |
| 탐색 연결 | 현재 장면의 특정 항목에서 이동할 세부 장면 ID |
| 분야 · 후속 | 분야 ID·표시 이름과 해당 분야의 전체 지도 장면. 분야 탭 모델은 아직 추가하지 않음 |

항목 하나에 전역적인 깊이나 단 하나의 부모를 강제하지 않는다. 같은 SDK나 표준이 여러 제품의 세부 지도에 나타날 수 있기 때문이다. 대표 항목과 세부 항목의 구분은 각 지도 장면의 노출 목록으로 관리하고, 설명·라이선스·출처는 공통 항목 데이터를 참조한다.

프로젝트·제품과 개념·규약의 종류를 구분한다. 개념에 공개 저장소나 소프트웨어 라이선스를 억지로 부여하지 않는다. 실제 제품·코드·모델 가중치에는 해당 범위의 조건을 유지한다.

관계는 화면상 가까이 놓였다는 이유로 생성하지 않는다. 공식 자료에서 확인한 구성·통합·의존·확장 관계만 등록하고, 선택적 연동과 필수 의존성, 실험적 기능과 안정 기능을 구분한다.

## 7. 구현 단계와 완료 기준

| 단계 | 사용자에게 보이는 결과 | 현재 상태 | 완료 확인 |
|---|---|---|---|
| 1. 한 항목의 세부 생태계 편집 | 대표 항목 하나에서 새 요소가 나오는 콘텐츠 구성 | 완료 · MCP·SDK 장면과 공식 자료 편집 | 신규 12개 항목·20개 관계의 출처·날짜·참조 검증 통과 |
| 2. 전체 → 세부 지도 구현 | 더블클릭·버튼으로 MCP 세부 지도를 펼치고 새로운 항목을 읽음 | 완료 · 브라우저·시각 검증 통과 | 데스크톱·모바일에서 새 항목 노출과 클릭·더블클릭·버튼 진입 확인 |
| 3. 다음 단계와 복귀 | TypeScript SDK로 한 단계 더 들어가고 이전 지도 복원 | 완료 · 탐색 상태 테스트와 브라우저 복귀 검증 통과 | 두 번의 세부 진입, 이전/전체 복귀와 선택·스크롤·포커스 복원, 키보드 동작 확인 |
| 4. 대표 항목에 확대 | 서로 다른 역할의 항목에서도 같은 방식으로 탐색 | 다음 작업 · 검증한 시범 구조에 대표 콘텐츠 추가 | 여러 장면이 동일 항목을 중복 생성하지 않고 재사용. 글자·연결 설명 겹침 없이 탐색 가능 |
| 5. 분야 탭 확장 | 콘텐츠가 준비된 다른 AI 분야로 이동 | 후속 · 분야별 대표·세부 콘텐츠 조사와 검수 필요 | 빈 탭 없이 분야에 맞는 지도와 세부 콘텐츠가 표시되며 공통 기술은 재사용됨 |

분야 탭 후보는 생성형 AI·에이전트, 비전·음성, 예측·추천, 로보틱스 등이다. 서로 배타적인 산업 분류로 고정하지 않고 탐색 관점으로 다룬다. 탭 명칭과 범위는 각 분야 콘텐츠를 준비할 때 결정한다.

## 8. 검증 항목

현재 `npm test` 27개, `npm run typecheck`, `npm run build`가 통과했다. 장면 참조·신규 항목 발견·공통 항목 재사용·출처와 탐색 상태를 자동 검증했다. 데스크톱 1440·1280px와 모바일 390·360px에서 클릭·더블클릭·버튼 진입, MCP → TypeScript SDK → 뒤로가기와 전체 경로 복귀, 선택·스크롤·포커스 복원을 확인했다. Enter·Escape와 모바일 포커스 제한, 가로 넘침도 검증하고 관계 라벨 겹침을 수정했다. 증거와 결과는 [디자인 QA](../design-qa.md)에 기록한다. 동작 줄이기는 코드에서 지원하며 해당 설정의 브라우저 시뮬레이션은 수행하지 않았다.

새 장면을 추가할 때도 다음 기준을 유지한다.

- 전체 지도에서 숨겨진 신규 세부 항목이 진입 후 나타나는지 확인한다. 새로 드러난 요소를 사용자가 그 역할과 연결 의미까지 설명할 수 있어야 한다.
- 세부 지도에 나오는 모든 기술 관계가 실제 항목을 참조하며 출처·검증일을 갖는지 검사한다.
- 한 번 클릭, 명시적 진입 버튼, 더블클릭이 서로 충돌하지 않는지 확인한다.
- 모바일·키보드로 진입, 항목 선택, 상세 열기·닫기, 다음 단계, 이전/전체 복귀가 가능해야 한다.
- 같은 요소를 반복 방문하거나 여러 경로로 방문해도 경로·복귀 상태가 일관되어야 한다.
- 세부 지도가 없는 항목과 관계 자료가 부족한 경우에도 잘못된 진입 동작이나 임의의 연결을 만들지 않는다.
- 연결선 전면 표시, 글자 대비, 이름·관계 설명 겹침, 다양한 화면 폭을 확인한다.
- 타입 검사·빌드·기존 수집 및 생태계 검증을 통과한다. 지도 장면 참조와 탐색 상태에 필요한 검증을 추가한다.

## 9. 이번 계획에서 제외하는 것

자동으로 관계를 추론하는 AI, 실시간 전체 웹 수집, 모든 항목의 무한 확장, 인기·시장 순위, 그래프 편집기, 관리자 화면, 계정·저장·개인화, 트래킹·뉴스·논문과의 깊은 연계는 포함하지 않는다. 기존 기능과 현재 공개 자료는 보존한다.

다음 실행 단위는 **검증한 세부 지도 구조에 다른 대표 항목의 콘텐츠를 추가하는 4단계**다. 이후 콘텐츠가 준비된 분야 탭을 5단계로 확장한다. 수집·공개 운영 준비는 별도 후속 작업으로 남긴다.
